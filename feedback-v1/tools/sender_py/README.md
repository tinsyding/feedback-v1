# 极方每周反馈程序（sender_py）

基于 **mss 整窗截图 + 相对比例自适应反推 + 阶梯级联多引擎判定（本地 OCR + 云端大模型）** 的企业微信学情反馈批量自动化发送器。

支持 **现代化 Web 版控制面板** 与 **经典桌面版（sv-ttk 浅色/深色主题）** 双界面形态；配备零发送防误发的多引擎基准评测模块、视口防出屏自动回弹守护，以及 GitHub Actions 自动化编译发布。

支持 Python 源码运行；GitHub Actions 会自动编译并发布三种打包形态（绿色文件夹版、Nuitka 原生机器码版、经典单文件版）。真实发送依赖 Windows + 企业微信桌面版；全套 95 项纯函数单元测试可在 Linux / Windows 免依赖秒级运行。

---

## 1. 它解决什么问题

旧版发送器依赖固定屏幕像素坐标，换电脑、改分辨率、调窗口大小或改 DPI 后极易截错区域、点错发错人。新版全面升级为：

1. **mss 整窗截取 + 视口防出屏守护**：截取企业微信完整窗口；当窗口飘出屏幕边缘时自动调用 Windows API 瞬间拉回安全可视区域；
2. **Qwen3.8-Max 预热智能标定 + 两框优雅兜底**：
   - 自动预先检索联系人（首位学生或系统内置「文件传输助手」）打开会话；
   - 优先通过 **Qwen3.8-Max** 多模态旗舰模型自动精准框选顶部标题栏与底部输入框，**老师全程无感，开箱即用免手动框选**；
   - 仅在 AI 识别异常时优雅回退到两框手动校准画板；
3. **三层阶梯式高精身份核验**：
   - **第 1 层**：winocr（Windows 原生 WinRT 内存直调，~47ms 极速放行）；
   - **第 2 层**：RapidOCR（ONNX 离线全流程 Det+Rec，~800ms 深度兜底）；
   - **第 3 层**：Qwen3.8-Flash（云端多模态大模型终极校验）；
   - **方案 1 智能容错**：在学号 100% 精确吻合的前提下，允许姓名存在 1 个字的 OCR 形近字/生僻字容错；
4. **安全红线 (Fail-Closed)**：
   - **群聊一律拦截**；
   - 身份未完全确认不放行；
   - 全局底层键盘钩子拦截 ESC 物理击键，停止发送时**绝不会导致企业微信最小化**；
   - 剪贴板双向写回读回核验，防错粘上一条消息。

## 3. 环境要求

- Windows 10 / 11（真实发送）
- 企业微信桌面版，已登录
- Python 3.10+（建议 3.11/3.12）
- 可访问判定服务端（默认 `https://feedback.wxjifang.cn`）
- 服务端 `api/identify.php` 已配置发送器令牌与视觉服务

安装依赖：

```powershell
cd feedback-v1\tools
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r sender_py\requirements.txt
```

Linux 只跑单测时不需要 `pywin32` / `mss`，安装基础依赖即可。

## 4. 发送器令牌说明

程序已内置内部默认访问令牌，**所有电脑均可开箱即用，无需手动配置任何令牌**。

如需覆盖为特定自定义令牌（可选），仍支持以下方式：

方式一：环境变量（可选）

```powershell
setx SENDER_API_TOKEN "你的自定义令牌"
```

设置后重新打开终端，使环境变量生效。

方式二：用户配置文件（可选）

```text
%USERPROFILE%\.sender_py\config.json
```

```json
{
  "token": "你的自定义令牌"
}
```

服务端对应配置在 `feedback-v1/api/secret_key.local.php`（可选）。

## 5. 输入格式

输入文件支持 JSON 数组或网站导出的 HTML 快照。JSON 每个元素至少包含：

```json
[
  {
    "studentName": "90001张三",
    "message": "张三家长您好，\n以下是本周反馈……"
  }
]
```

- `studentName` 会原样用于企业微信搜索，请按企微通讯录里能搜到的写法填写；学号可以加在姓名前。
- 发送器会从中解析学号和姓名，支持：
  - `90001张三`
  - `90001,张三`
  - `90001，张三`
  - `90001-张三`
- `message` 中的 `\n` 会原样保留。
- **必须带学号**。服务端判定要求标题同时包含「学号 + 姓名」才返回 `matched: true`；学号缺失会因无法确认身份而不放行（fail-closed）。无学号姓名兜底只存在于家长端历史查询，不适用于发送器身份判定。
- 真实学生名单、聊天内容、截图都属于 PII，请放在本地或已被 `.gitignore` 排除的文件中，不要提交。

除 JSON 外，也支持网站「导出报告 → HTML 快照」生成的文件：

- 新版快照会优先读取内嵌的 `feedback-data` JSON，换行和特殊字符能原样保留；
- 旧版快照没有内嵌数据时，会从表格里的 `student-name` / `feedback-content` 提取；
- 文件选择框可以同时混选 JSON 和 HTML。

运行：

```powershell
cd feedback-v1\tools

# 方式一：现代化 Web 控制面板（推荐，浏览器交互、支持多引擎评测与报告在线查阅）
python sender_py\web_main.py

# 方式二：经典桌面版（Tkinter + sv-ttk 浅色/深色主题）
python sender_py\sender.py --input 测试.json
```

启动后，可点「选择文件」或直接拖拽一次选中多个 JSON 或网页 HTML 快照。发送器会自动合并这些文件，按「学号 + 姓名」去重，并在界面上显示已选文件数和合并后的学生总数；同一学生在多个文件中重复时只保留第一次出现的那条。

首页会列出全部已加载学生，每行包含：

- 勾选框：取消勾选后，本次「开始发送」会跳过该学生；
- 学号、姓名和状态（待发送、发送中、已发送、发送失败、已跳过、已拦截、未匹配）；
- 「复制学号姓名」和「复制话术」两个按钮，失败时可手动复制到企业微信；
- 双击状态列可查看该学生最后一次处理/失败原因；
- 「全选全部 / 全不选全部」和已勾选人数汇总（作用于全部已加载学生，不受搜索/筛选影响）。

搜索与失败处理：

- 搜索框按学号、姓名或 `studentName` 实时筛选，不影响已勾选状态；
- 状态筛选支持「全部、待发送、已发送、失败/未匹配、已跳过、已拦截」；
- 「只看失败」快速筛出失败/未匹配项；
- 「重试失败项」会取消其他勾选，只勾选失败/未匹配学生，并切到失败筛选，方便直接重试。

发送与停止：

- 点「开始发送」后会先弹窗确认本次人数；如果筛选/搜索隐藏了已勾选学生，确认框会明确提示；
- 发送中显示当前进度、当前学生和每人的状态；
- 发送中可按 **Esc** 或点「停止发送 (Esc)」请求停止。为保证不发出半条消息，会在当前学生处理完后停止，剩余已勾选学生标记为「已跳过」；
- 结束后显示本批汇总（成功/失败/拦截/未匹配/跳过），并可点「复制失败名单」复制失败/未匹配学生的学号姓名、状态和原因。

首页不显示日志；日志收在「运行日志」按钮打开的独立窗口里，可随时查看或清空。

`--input` 仍然作为启动时预加载的单个文件，支持 JSON 和 HTML；之后可以在界面里重新选择。

可选参数：

```text
--input    输入 JSON / HTML 路径；省略时尝试 测试.json，不存在则启动后选择
--server   判定服务端，默认 https://feedback.wxjifang.cn
--version  打印程序名与版本后退出
```

## 6. 首次使用：窗口校准

第一次运行、或企业微信窗口尺寸/DPI 发生变化时，会触发企业微信窗口视窗校准。校准优先采用 **AI 智能全自动标定**，失败时优雅回退至**手动框选画板**。

### 方式一：Qwen3.8-Max 预热智能标定（优先推荐，全自动无感）

1. **自动预热进会话**：程序先将企业微信激活至前台，并自动通过快捷键检索首位学生（或自动兜底检索系统内置联系人「文件传输助手」）并回车进入具体聊天窗口；彻底解决企业微信刚启动停在主页/未进聊天导致的识别盲区；
2. **多模态大模型精确定位**：通过 `api/calibrate_roi.php` 调用 **Qwen3.8-Max** 旗舰多模态模型，直接识别当前右侧会话的顶部标题栏（蓝框）与底部输入框（红框）；
3. **几何推导与自动生效**：客户端校验坐标合法性，自动几何反推中间聊天区域，写入配置文件并立即生效，**教师全程无须任何手工操作**。

### 方式二：手动交互框选（优雅兜底）

若网络离线、大模型识别超时或返回坐标异常，程序会自动弹出居中画板回退为手动校准：

1. 先点「知道了，开始框选」；
2. 在截图上框出**顶部标题栏**（蓝框）；
3. 再框出**底部输入框**（红框）；
4. 中间聊天区会自动生成绿色虚线预览；
5. 确认后保存。

规则：
- 只允许两个框，聊天区不允许手框；
- 每个框在原图尺度上宽 ≥ 40、高 ≥ 20；
- 输入框必须在标题栏下方；
- 反推聊天区高度至少 40px；
- 两框都必须在截图范围内。

保存位置：

```text
%USERPROFILE%\.sender_py\roi_config.json
```

配置按窗口签名 `宽x高@DPI缩放` 分组，ROI 存的是相对比例。因此：
- 拖动窗口位置：不需要重新校准；
- 改变窗口大小：签名变化，自动触发重新校准；
- 换显示器 / 改缩放：DPI 变化，自动触发重新校准；
- 企业微信 UI 大改版：可能需要重新校准或调整代码。

界面顶部常驻「🎯 校准视野」按钮，可随时点击一键重新触发 AI 自动校准。

Windows 冒烟验证：

```powershell
cd feedback-v1\tools
python sender_py\verify_stage2_win.py
python sender_py\verify_stage4_win.py
```

脚本会在 `%TEMP%` 下生成调试截图/ROI 配置，验收后请清理，不要提交。

## 7. 发送流程与阶梯核验

每个学生：

1. **唤起与视口防出屏守护**：唤起企业微信主窗口；若检测到窗口部分飘出屏幕（如 `left < 0` 藏在屏幕左侧边缘），自动调用 Windows API 瞬间拉回屏幕安全可视区并等待重绘；
2. **视窗签名自检**：检查 ROI 签名，命中缓存直接使用，未命中则触发上述预热 AI 标定；
3. **搜人进会话**：`Ctrl+F` 检索学生，按候选 1 → 2 → 3 机械切换定位；若弹出企业微信「全局搜索」窗口（表明未搜到联系人），程序自动关闭该弹窗并跳过剩余候选；
4. **截窗裁剪**：`mss` 抓取整窗像素，裁剪出标题栏与聊天区尾部；
5. **阶梯式智能核验（本地优先，云端大模型兜底）**：
   - **第 1 层 (winocr)**：Windows 原生 WinRT 内存直调，~47ms 极速放行（准确率 ~84%）；
   - **第 2 层 (RapidOCR)**：ONNXRuntime 离线 Det+Rec 全流程，~800ms 深度稳健兜底（准确率 100%）；
   - **第 3 层 (Qwen3.8-Flash)**：云端极速多模态视觉模型秒验（仅在本地未通过或特定模式下介入）；
   - **方案 1 智能容错**：在学号精准吻合且非群聊的前提下，利用编辑距离算法对中文姓名提供最多 1 个字的 OCR 形近字/生僻字容错（如“胡耔墨”与“胡籽墨”）；
6. **判定动作决策**：
   - `is_group = true` → **红线拦截，绝不发送**；
   - `matched = true` → 剪贴板双向核验并模拟粘贴回车发送；
   - `matched` 缺失或非 true → **不放行**，换下一候选；
   - 抓帧/接口失败 → 换下一候选；
   - 3 个候选都不匹配 → 记为 `unmatched`，不发送；
7. **防风控节奏停顿**：发送后执行平滑随机微停顿，进入下一学生。

紧急停止保障：
- 发送中可按 **Esc** 键或点界面「停止 (Esc)」请求停止；
- 采用 **Windows 底层键盘钩子 (WH_KEYBOARD_LL)** 拦截物理 ESC 键击并直接吞掉击键，**彻底杜绝了按 Esc 导致前台企业微信被意外最小化的问题**；
- 程序会在当前学生的安全边界平稳停止，剩余学生标记为「已跳过」。

## 8. 本地历史、已发记录与待回名单

### 发送历史（断点续发）

```text
%USERPROFILE%\.sender_py\feedback_history.json
```

- 存档键为「输入文件名 [第 1 周]」，兼容旧版 `{"classes": {...}}` 结构；
- 默认开启“已发送自动跳过”（`SKIP_SENT = True`），重启程序重新载入文件时，会自动跳过已发学生，实现断点无缝续发。

### 本地已发记录归档 (SentFilesManager)

每次批次发送完成后，程序会自动在本地生成独立的归档文件：
- **JSON 数据记录**：`%USERPROFILE%\.sender_py\sent_records/{时间戳}_{文件名}_已发记录.json`；
- **独立 HTML 快照报告**：`%USERPROFILE%\.sender_py\sent_records/{时间戳}_{文件名}_已发记录.html`，无需联网，在任意浏览器双击即可直观查看当批次学生、状态与对应话术；
- 在 Web 控制面板中可点击「已发文件」直接在线预览 HTML 报告或一键打开本地记录目录。

### 待回名单管理

- 发送过程中，后台异步分析线程自动提取每位家长的最后一条消息与回复意向；
- 界面「📨 待回名单」只展示明确需要回复（`needs_reply=true`）或待人工确认（`needs_reply` 判不出）的学员；
- **表格列精简清晰**：包含「学号 | 姓名 | 判定 | 最新家长留言 | 操作」，移除了冗余的企微窗口标题；
- **独立复制按钮与颜色标记**：每一行配备专属「复制」按钮，点击复制后学号与姓名之间**不加空格**（如 `90001张三`），整行背景自动标记为浅绿高亮（`#f0fdf4`），按钮变为 `✓ 已复制`，方便老师逐一处理且绝不遗漏或重复；
- **导出 CSV**：支持一键导出带 BOM 的 UTF-8 CSV 表格，Excel 直接打开无乱码；
- **待回名单仅保存在本地内存与本地文件，绝不向云端回传**。

## 12. 打包模式与防杀软误报指南

由于发送器调用了 Windows 截图与自动化操作 API，且未购买昂贵的商业代码签名，在部分杀软（如 360 安全卫士、火绒、Windows Defender）下可能触发启发式误报。为此项目提供了 **三种打包模式**：

| 打包模式 | 产物形式 | 运行机制 | 杀软误报率 | 推荐使用场景 | 本地打包脚本 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **1. 绿色文件夹版**<br>(`--onedir`) | ZIP 压缩包<br>(解压为一个文件夹) | 直接调用文件夹内部 DLL 与依赖，**绝不解压到 Temp 临时目录** | **极低** (降 80%+) | **日常教师分发首选**，解压到桌面双击 exe 即可 | 双击 `build_onedir.bat` |
| **2. Nuitka 原生机器码版**<br>(`C++ 原生编译`) | ZIP 压缩包<br>(原生二进制文件夹) | Python 源码直接翻译为 C++ 并编译为 PE 机器码，**彻底脱离 Python 打包特征** | **几乎 0 误报** | 杀软环境严苛、360 极度敏感的学校机房 | 双击 `build_nuitka.bat` |
| **3. 经典单文件版**<br>(`--onefile`) | 单个 `.exe` 文件 | 双击后自解压至 `AppData\Local\Temp` 运行 | 中~高 (易被360 QVM引擎启发式拦截) | 临时快速演示、单文件携带便利 | 双击 `build_onefile.bat` |

> 💡 **本地一键打包**：直接双击 `tools/sender_py/build_all.bat`，即可呼出控制面板自由选择一键打包上述对应版本。
>
> 🚀 **CI/CD 自动构建**：向仓库推送 tag（如 `sender-v1.8.11`）或在 GitHub Actions 手动执行工作流时，均会自动编译并发布全套产物。

## 13. 当前限制

- GitHub Actions 的 Windows Artifact/Release 未签名，仅供内测/验证；若使用单文件版在 360 环境下被拦截，推荐换用**绿色文件夹版**或 **Nuitka 原生编译版**，或直接向 360 开放平台提交误报白名单申请；
- GitHub Releases 会自动改写中文附件名，因此 Release 同时提供英文名 exe 与内含中文名 exe 的 zip；
- 真实发送依赖 Windows + 企业微信桌面版；
- 企业微信 UI 改版可能导致搜索/候选定位失效，需要真机回归；
- 停止发送是安全边界停止：不强行打断正在粘贴/发送的消息，当前学生结束后停止，避免发出半条；
- ROI 只支持「标题栏 + 输入框」两框，聊天区自动反推；
- 云端视觉服务不可用时不会降级为“盲发”，只会自动降级本地 OCR 备用通道或跳过候选。

## 14. 常见问题

**Q：提示“缺少发送器令牌”或“鉴权失败”？**

新版已内置默认小范围内部令牌，默认无需配置即可使用。如果遇到鉴权失败，请确认服务端接口已部署最新版本，或检查当前终端环境变量 `SENDER_API_TOKEN` 是否被误配。

**Q：一直要求重新校准？**

确认企业微信窗口大小和系统缩放没有变化；校准保存的签名是 `宽x高@DPI缩放`，任何一项变化都会触发重校准。

**Q：截图截到了别的窗口？**

发送器会尝试把企微唤到前台并归位；仍失败时会报错停止。请手动把企微完整露出来再重试。

**Q：为什么明明搜到了学生却不发？**

身份判定没有明确 `matched: true`，或命中了群聊拦截。这是 fail-closed 设计，优先保证不发错人。查看界面日志中的候选判定原因。

**Q：待回名单会上传吗？**

不会。待回名单只写本地 JSON/CSV，不自动上报云端。
