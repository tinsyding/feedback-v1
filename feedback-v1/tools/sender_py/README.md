# 极方每周反馈程序（sender_py）

基于 **mss 整窗截图 + ROI 相对比例反推 + 云端两图判定** 的企业微信反馈发送器。主界面使用 sv-ttk 浅色主题、网站 favicon 作为程序图标，GitHub Actions 可打包单文件 Windows exe。

支持源码运行；GitHub Actions 会生成未签名的单文件 `极方每周反馈程序.exe`，并在推送 `sender-*` tag 时自动发布 GitHub Release。真实发送只支持 Windows；Linux 可运行全部纯函数单测。

---

## 1. 它解决什么问题

旧版发送器依赖固定屏幕坐标，换电脑、改分辨率、调窗口大小或改 DPI 后容易截错区域、发错人。新版改为：

1. 用 `mss` 截取企业微信**完整窗口**；
2. 只让老师框两个区域：**顶部标题栏**、**底部输入框**，中间聊天区由两框自动反推；
3. 所有 ROI 都以**相对比例**保存，窗口移动不影响；窗口尺寸或 DPI 变化时自动要求重新校准；
4. 每次只裁出「标题栏 + 聊天区末尾」两张小图，上传给 `api/identify.php` 判定当前会话是不是目标学生；
5. **身份不匹配不放行、群聊一律拦截**；判定不确定时换下一个候选，最多 3 个。

## 3. 环境要求

- Windows 10 / 11（真实发送）
- 企业微信桌面版，已登录
- Python 3.10+（建议 3.11/3.12）
- 可访问判定服务端（默认 `https://feedback.wxjifang.cn`）
- 服务端 `api/identify.php` 已配置发送器令牌与视觉服务

安装依赖：

```powershell
cd feedback-v1\tools
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r sender_py\requirements.txt
```

Linux 只跑单测时不需要 `pywin32` / `mss`，安装基础依赖即可。

## 4. 发送器令牌说明

程序已内置内部默认访问令牌，**所有电脑均可开箱即用，无需手动配置任何令牌**。

如需覆盖为特定自定义令牌（可选），仍支持以下方式：

方式一：环境变量（可选）

```powershell
setx SENDER_API_TOKEN "你的自定义令牌"
```

设置后重新打开终端，使环境变量生效。

方式二：用户配置文件（可选）

```text
%USERPROFILE%\.sender_py\config.json
```

```json
{
  "token": "你的自定义令牌"
}
```

服务端对应配置在 `feedback-v1/api/secret_key.local.php`（可选）。

## 5. 输入格式

输入文件支持 JSON 数组或网站导出的 HTML 快照。JSON 每个元素至少包含：

```json
[
  {
    "studentName": "90001张三",
    "message": "张三家长您好，\n以下是本周反馈……"
  }
]
```

- `studentName` 会原样用于企业微信搜索，请按企微通讯录里能搜到的写法填写；学号可以加在姓名前。
- 发送器会从中解析学号和姓名，支持：
  - `90001张三`
  - `90001,张三`
  - `90001，张三`
  - `90001-张三`
- `message` 中的 `\n` 会原样保留。
- **必须带学号**。服务端判定要求标题同时包含「学号 + 姓名」才返回 `matched: true`；学号缺失会因无法确认身份而不放行（fail-closed）。无学号姓名兜底只存在于家长端历史查询，不适用于发送器身份判定。
- 真实学生名单、聊天内容、截图都属于 PII，请放在本地或已被 `.gitignore` 排除的文件中，不要提交。

除 JSON 外，也支持网站「导出报告 → HTML 快照」生成的文件：

- 新版快照会优先读取内嵌的 `feedback-data` JSON，换行和特殊字符能原样保留；
- 旧版快照没有内嵌数据时，会从表格里的 `student-name` / `feedback-content` 提取；
- 文件选择框可以同时混选 JSON 和 HTML。

运行：

```powershell
cd feedback-v1\tools
python sender_py\sender.py --input 测试.json
```

启动 GUI 后，可点「选择 JSON / HTML 文件（可多选）」一次选中多个 JSON 或网页 HTML 快照。发送器会合并这些文件，按「学号 + 姓名」去重，并在界面上显示已选文件数和合并后的学生总数；同一学生在多个文件中重复时只保留第一次出现的那条。

首页会列出全部已加载学生，每行包含：

- 勾选框：取消勾选后，本次「开始发送」会跳过该学生；
- 学号、姓名和状态（待发送、发送中、已发送、发送失败、已跳过、已拦截、未匹配）；
- 「复制学号姓名」和「复制话术」两个按钮，失败时可手动复制到企业微信；
- 双击状态列可查看该学生最后一次处理/失败原因；
- 「全选全部 / 全不选全部」和已勾选人数汇总（作用于全部已加载学生，不受搜索/筛选影响）。

搜索与失败处理：

- 搜索框按学号、姓名或 `studentName` 实时筛选，不影响已勾选状态；
- 状态筛选支持「全部、待发送、已发送、失败/未匹配、已跳过、已拦截」；
- 「只看失败」快速筛出失败/未匹配项；
- 「重试失败项」会取消其他勾选，只勾选失败/未匹配学生，并切到失败筛选，方便直接重试。

发送与停止：

- 点「开始发送」后会先弹窗确认本次人数；如果筛选/搜索隐藏了已勾选学生，确认框会明确提示；
- 发送中显示当前进度、当前学生和每人的状态；
- 发送中可按 **Esc** 或点「停止发送 (Esc)」请求停止。为保证不发出半条消息，会在当前学生处理完后停止，剩余已勾选学生标记为「已跳过」；
- 结束后显示本批汇总（成功/失败/拦截/未匹配/跳过），并可点「复制失败名单」复制失败/未匹配学生的学号姓名、状态和原因。

首页不显示日志；日志收在「运行日志」按钮打开的独立窗口里，可随时查看或清空。

`--input` 仍然作为启动时预加载的单个文件，支持 JSON 和 HTML；之后可以在界面里重新选择。

可选参数：

```text
--input    输入 JSON / HTML 路径；省略时尝试 测试.json，不存在则启动后选择
--server   判定服务端，默认 https://feedback.wxjifang.cn
--version  打印程序名与版本后退出
```

## 6. 首次使用：窗口校准

第一次运行、或企业微信窗口尺寸/DPI 发生变化时，会弹出「企业微信窗口校准」窗口。

操作顺序：

1. 先点「知道了，开始框选」；
2. 在截图上框出**顶部标题栏**（蓝框）；
3. 再框出**底部输入框**（红框）；
4. 中间聊天区会自动生成绿色虚线预览；
5. 确认后保存。

规则：

- 只允许两个框，聊天区不允许手框；
- 每个框在原图尺度上宽 ≥ 40、高 ≥ 20；
- 输入框必须在标题栏下方；
- 反推聊天区高度至少 40px；
- 两框都必须在截图范围内。

保存位置：

```text
%USERPROFILE%\.sender_py\roi_config.json
```

配置按窗口签名 `宽x高@DPI缩放` 分组，ROI 存的是相对比例。因此：

- 拖动窗口位置：不需要重新校准；
- 改变窗口大小：签名变化，自动要求重新校准；
- 换显示器 / 改缩放：DPI 变化，自动要求重新校准；
- 企业微信 UI 大改版：可能需要重新校准或调整代码。

界面已移除「重新校准 ROI」按钮。需要强制重校准某个窗口时，退出程序后删除 `%USERPROFILE%\.sender_py\roi_config.json`（或只删对应签名），下次运行会自动重新弹出校准窗口。

Windows 冒烟验证：

```powershell
cd feedback-v1\tools
python sender_py\verify_stage2_win.py
python sender_py\verify_stage4_win.py
```

脚本会在 `%TEMP%` 下生成调试截图/ROI 配置，验收后请清理，不要提交。

## 7. 发送流程

每个学生：

1. 唤起企业微信并确保窗口完整可见；
2. 检查 ROI 签名，必要时先校准；
3. `Ctrl+F` 搜索学生，按候选 1 → 2 → 3 机械切换；
4. `mss` 截整窗，裁出标题栏与聊天区末尾；
5. 上传两张图到 `api/identify.php` 判定；
6. 判定结果：
   - `is_group = true` → **拦截，不发送**；
   - `matched = true` → 剪贴板粘贴并发送；
   - `matched` 缺失或非 true → **不放行**，换下一候选；
   - 抓帧/接口失败 → 换下一候选；
   - 3 个候选都不匹配 → 记为 `unmatched`，不发送；
7. 发送后随机停顿，进入下一学生。

发送中可按 **Esc** 或点「停止发送 (Esc)」请求停止；程序会在当前学生的安全边界停止（不会强行打断正在粘贴/发送的消息），剩余已勾选学生标记为「已跳过」。

安全细节：

- 发送前确认企业微信在前台，截图不会被其他窗口遮挡；
- 剪贴板写入后会读回核验，粘贴后再核验一次，防止粘错上一条内容；
- 群聊无论标题多像都拦截；
- 身份判定 fail-closed：只有明确 `matched: true` 才发送；
- `needs_reply` 判不出时 fail-open：照发，但在待回名单里记「待人工确认」。

随机停顿上限：

```text
换候选：0.3 ~ 0.8 秒
发送后：0.4 ~ 1.0 秒
换学生：0.5 ~ 1.0 秒
```

全部 ≤ 1 秒。

## 8. 本地历史与待回名单

### 发送历史

```text
%USERPROFILE%\.sender_py\feedback_history.json
```

- 存档键为「输入文件名 [第 1 周]」，兼容旧版 `{"classes": {...}}` 结构；
- 多文件选择时，每条记录按来源文件分别存档；
- 当前临时关闭“已发送自动跳过”（`sender.py` 的 `SKIP_SENT = False`），历史仍会记录，但重复运行会再次发送；恢复时改为 `True`；
- 旧版历史可以直接读取，不需要手工转换。

### 待回名单

- 每次进入候选会话，若聊天区有可读内容，会记录候选信息；
- 界面「📨 待回名单」只展示明确需要回复（`needs_reply=true`）或待人工确认（`needs_reply` 判不出）的人，明确无需回复的不会展示，也不会导出；
- 数量角标和列表使用同一过滤结果；
- 表头精简为「学生 / 会话 / 最后消息 / 需回 / 时间」；
- 选中一行后点「复制选中学生学号姓名」，或直接双击该行，即可复制学生信息；
- CSV 使用同样的中文精简表头，带 BOM，Excel 直接打开不乱码；
- **待回名单只存在本地，不自动上传云端**。

## 10. 数据与隐私边界

- 判定时通过 HTTPS 上传两张裁剪图（`title.png`、`chat_tail.png`）及 `target_id` / `target_name` 等请求字段；
- 服务端收到后存档两图 + 请求/返回 JSON，用于举证复盘，当前保留 **14 天**；
- 客户端本地默认不长期保存判定原图；
- 待回名单只存本地，不自动上报；
- 发送器令牌、服务端视觉密钥、真实学生 PII 均不得提交到 Git；
- 群聊拦截、身份 fail-closed、剪贴板核验均为硬性红线，不要为了“发得快”绕过。

## 12. 打包模式与防杀软误报指南

由于发送器调用了 Windows 截图与自动化操作 API，且未购买昂贵的商业代码签名，在部分杀软（如 360 安全卫士、火绒、Windows Defender）下可能触发启发式误报。为此项目提供了 **三种打包模式**：

| 打包模式 | 产物形式 | 运行机制 | 杀软误报率 | 推荐使用场景 | 本地打包脚本 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **1. 绿色文件夹版**<br>(`--onedir`) | ZIP 压缩包<br>(解压为一个文件夹) | 直接调用文件夹内部 DLL 与依赖，**绝不解压到 Temp 临时目录** | **极低** (降 80%+) | **日常教师分发首选**，解压到桌面双击 exe 即可 | 双击 `build_onedir.bat` |
| **2. Nuitka 原生机器码版**<br>(`C++ 原生编译`) | ZIP 压缩包<br>(原生二进制文件夹) | Python 源码直接翻译为 C++ 并编译为 PE 机器码，**彻底脱离 Python 打包特征** | **几乎 0 误报** | 杀软环境严苛、360 极度敏感的学校机房 | 双击 `build_nuitka.bat` |
| **3. 经典单文件版**<br>(`--onefile`) | 单个 `.exe` 文件 | 双击后自解压至 `AppData\Local\Temp` 运行 | 中~高 (易被360 QVM引擎启发式拦截) | 临时快速演示、单文件携带便利 | 双击 `build_onefile.bat` |

> 💡 **本地一键打包**：直接双击 `tools/sender_py/build_all.bat`，即可呼出控制面板自由选择一键打包上述对应版本。
>
> 🚀 **CI/CD 自动构建**：每次向仓库推送 tag（如 `sender-v1.8.7`）或在 GitHub Actions 手动执行工作流时，均会自动编译并发布全套三种模式的产物。

## 13. 当前限制

- GitHub Actions 的 Windows Artifact/Release 未签名，仅供内测/验证；若使用单文件版在 360 环境下被拦截，推荐换用**绿色文件夹版**或 **Nuitka 原生编译版**，或直接向 360 开放平台提交误报白名单申请；
- GitHub Releases 会自动改写中文附件名，因此 Release 同时提供英文名 exe 与内含中文名 exe 的 zip；
- 真实发送依赖 Windows + 企业微信桌面版；
- 企业微信 UI 改版可能导致搜索/候选定位失效，需要真机回归；
- 停止发送是安全边界停止：不强行打断正在粘贴/发送的消息，当前学生结束后停止，避免发出半条；
- ROI 只支持「标题栏 + 输入框」两框，聊天区自动反推；
- 云端视觉服务不可用时不会降级为“盲发”，只会不发送/换候选。

## 13. 常见问题

**Q：提示“缺少发送器令牌”或“鉴权失败”？**

新版已内置默认小范围内部令牌，默认无需配置即可使用。如果遇到鉴权失败，请确认服务端接口已部署最新版本，或检查当前终端环境变量 `SENDER_API_TOKEN` 是否被误配。

**Q：一直要求重新校准？**

确认企业微信窗口大小和系统缩放没有变化；校准保存的签名是 `宽x高@DPI缩放`，任何一项变化都会触发重校准。

**Q：截图截到了别的窗口？**

发送器会尝试把企微唤到前台并归位；仍失败时会报错停止。请手动把企微完整露出来再重试。

**Q：为什么明明搜到了学生却不发？**

身份判定没有明确 `matched: true`，或命中了群聊拦截。这是 fail-closed 设计，优先保证不发错人。查看界面日志中的候选判定原因。

**Q：待回名单会上传吗？**

不会。待回名单只写本地 JSON/CSV，不自动上报云端。
